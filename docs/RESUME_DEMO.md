# EmberFrame：简历五条技术的现场演示

核验日期：2026-10-05。讲稿约 5 分钟，现场操作约 6–8 分钟；导出与回归另计。

操作约 6–8 分钟。推荐入口：**双击根目录 `Start-Resume-Demo.cmd`**，在顶部“演示”菜单依次选配置。所有配置仍使用正常 Scene、材质、GPU 管线和检查器，没有替身画面。

## 0. 面试演示讲稿

（进入“演示 → 1 物理材质与 IBL”，调整一个材质球的粗糙度。）

这个项目是在 Vulkan Guide 基线上的实时渲染框架。我保留了上游来源，新增的是统一的算法工作台，以及这里展示的材质、阴影、屏幕空间、预计算和几何管理。基础初始化和原始教程章节不作为个人新增成果。

材质使用 Cook–Torrance/GGX。实时环境反射没有在每个像素上重新遍历环境所有方向，而是使用预过滤环境数据与 BRDF LUT 组成 Split-Sum 近似。粗糙度会改变预过滤层级和反射的宽度。

（进入“KC 白炉对照”，在“渲染 → 材质与采样”开关能量补偿。）

这里去掉了直接灯和 Bloom，只保留单位常量环境与白色粗糙金属。关闭补偿时，单次散射模型会损失能量；开启 Kulla–Conty 后，球面亮度更接近单位环境。对照保持曝光、模型、材质和相机不变，因此不是把灯调亮来制造效果。

（进入“2 多光源与 GPU 剔除”，显示“每组灯数”。）

前向和延迟都是实际 Vulkan 路径。Tiled 按屏幕分块，Clustered 再按深度分层，Compute 为每组生成灯表；物体包围球通过视锥测试后，GPU 写入间接绘制参数。场景中还保留了真实的视野外实例，因此可以核对候选和可见数量。这里的灯表与剔除结果是功能证据，性能是否更好要看另外采集的 GPU 时间，而不是凭颜色判断。

（进入“3 实时阴影”，切 PCSS、CSM 和 MSM。）

PCSS 先估计遮挡物深度，再决定半影滤波范围。CSM 用多个方向光投影分配近远阴影精度，并通过纹素对齐稳定投影。VSM、VSSM 和四矩 MSM 是同场景下的替代方案；统计近似仍可能漏光。倾斜接收面的深度校正用于减少自阴影，不是直接增大 Bias 或关闭阴影。

（进入“4 屏幕空间与时域”，启动平移回放，开关 TAA/SVGF。）

SSR 与 SSGI 从当前深度记录进行屏幕空间射线查询，不能知道屏幕外或被第一层遮挡后的完整场景。TAA 使用投影 jitter、相机运动重投影、历史拒绝和邻域钳制；基础 SVGF 用历史矩和方差引导多尺度滤波。这里连续移动相机，可以观察历史是否复用、是否出现拖影；运动物体当前会使相关历史失效，不能宣称已经支持完整蒙皮运动向量。

（进入“5 预计算”，切 SH/PRT；然后进入“几何与 LOD”。）

SH 表示低阶环境照明，静态漫反射 PRT 预先保存可见性传输；镜面 IBL 仍然保留。BVH/SAH 用在 CPU 参考路径追踪与场景查询。QEM 先生成真正减面的 LOD 链，运行时按投影误差选级。原网格保留，不在每帧重新减面；拉远相机时能看到实际提交三角形减少，靠近时恢复细节。

## 1. 本次演示要讲清楚什么

五条简历不是五个名词清单：每条都对应**真实操作、可观察结果、统计或数值证据，以及一个限制**。

会前关闭其他工作台，先启动一次确认资源完成。请不要现场下载临时模型，也不要同时运行性能采样和交互程序。

| 简历条目 | 固定配置 | 重点证据 |
|---|---|---|
| 物理材质与光照 | `pbr`、`kc` | 粗糙度变化、白炉补偿开关及线性 HDR 数值 |
| 管线与 GPU 剔除 | `lights` | 前向/延迟、灯表、实际可见对象、独立 GPU timestamp |
| 实时阴影 | `shadows` | 七种阴影可见性、PCSS 最终颜色、CSM 连续运动 |
| 屏幕空间与时域重建 | `temporal` | 环境/SSR/SSGI、TAA/SVGF 左右连续帧 |
| 预计算与几何优化 | `shadows`、`geometry` | SH/PRT、BVH 命中一致与求交次数、实际 LOD 选级 |

配置可以自由修改。重新选择“演示”菜单项目会恢复该固定配置并清空当前撤销历史；它不会自动覆盖已保存的 `.ember` 工程。

## 2. 第一步：PBR、IBL 与能量补偿，约 1 分钟

**操作**

1. 选“演示 → 1 物理材质与 IBL”。左侧选材质，在“材质”页调整“粗糙度”和“金属度”。
2. 顶部执行路径在“Vulkan 前向 / Vulkan 延迟”之间切换，保持相机与材质相同。
3. 选“演示 → KC 白炉对照”。在“渲染 → 材质与采样”开关“能量补偿”。不要再调曝光或灯光。

**预期结果**

粗糙度改变高光宽度和环境反射细节；白炉中粗糙金属开启 KC 后明显变亮。白炉中心的线性 RGB 保存在演示包 `01-kc-off/stats.json` 与 `01-kc-on/stats.json`，显示图片已经 Tone Mapping，不能直接把屏幕像素值当成线性能量。

讲解：

> 我固定了场景与曝光，只切换多次散射能量补偿。画面用于直观观察，线性 HDR 读回用于核对能量，二者不混用。

**面试追问入口**：GGX 的作用、Split-Sum 的两部分、粗糙度与 Mip、Kulla–Conty 补偿什么。

**边界**：当前环境来自解析天空预过滤，不是已完成外部 HDR 文件导入；白炉是受控测试，不证明任意材质都无误差。

## 3. 第二步：管线、灯表与实际剔除，约 1 分钟

**操作**

1. 选“演示 → 2 多光源与 GPU 剔除”。切换前向/延迟，显示“世界法线”，再回最终颜色。
2. “渲染 → 光照与可见性 → 光源筛选”依次选“全部灯 / Tiled 分块 / Clustered 聚簇”。
3. 顶部显示模式选“每组灯数”。然后回最终颜色，移动相机；鼠标悬停底部 GPU 统计，查看“可见 / 候选”。
4. 展示演示包六组 `benchmark-*` 的 `gpu-timings.json`，而不是报截图过程的时间。

**预期结果**

灯表颜色随空间分组变化；固定最终颜色不应因为减少无关灯计算而改变。脚本实际比较全灯/Tiled/Clustered 的线性 HDR，`summary.json` 保存误差；前向/延迟也有同场景对照。候选包含故意放到视锥外的真实实例，可见数量应更小。GPU 报告先预热 30 个有效完成帧，再采独立的完成 serial。

前向/延迟不是逐像素完全相同：G-buffer 法线量化在极尖锐高光处可放大 HDR 差异。报告保留平均误差、最大绝对/归一化误差和超过 0.01 的通道比例；不能把“小平均误差”说成“峰值处也没有差异”。灯表替换仍独立核对最大误差。

讲解：

> Compute 生成灯表与间接参数，绘制从 GPU Buffer 读取。减少计算并不意味着小场景一定更快，建表成本也要计入，所以我保留全灯、分块和聚簇六组原始计时。

**边界**：最多 64 盏灯；逐 Primitive Indirect Draw，不宣称单次 MultiDrawIndirect。可见/三角形统计来自已完成帧，UI Draw 命令数不是同一个计数范围。

## 4. 第三步：阴影算法与相机运动，约 1–2 分钟

**操作**

1. 选“演示 → 3 实时阴影”。“渲染 → 光照与可见性 → 阴影”依次选 Hard、PCF、PCSS。
2. “质量与算法参数”调整“光源尺度”，观察 PCSS 边缘；保持其他参数不变。
3. 选 CSM，顶部显示“阴影可见性”，启动“演示 → 平移回放 / TAA、CSM”。回最终颜色观察。
4. 停止回放，再切 VSM + SAT、VSSM、MSM。需要清楚区分时使用演示包七张可见性图。

**预期结果**

PCSS 滤波范围随遮挡关系变化，CSM 在相机连续小幅平移时更新级联。可见性图白色表示可见、黑色表示遮挡。包中 `video-shadow-left-PCF-right-CSM/comparison.mp4` 左为单张 PCF，右为稳定化 CSM，相机轨迹逐帧一致。

讲解：

> 这两边比较的是完整阴影方案，不能把全部差异都归因于纹素对齐。纹素对齐本身另有投影数值检查；这里展示实际运动下的阴影结果。

**接收平面校正证据**：原有 GPU 集成检查包含倾斜平面与相距 0.015 世界单位的近遮挡者。默认 Bias 仍为 0.002；校正减少自阴影，同时不把近遮挡一并消掉。包不再声称包含“旧 Bug Shader”的现场开关。

**边界**：统计阴影可能漏光；方向光正交阴影与点光源全向阴影不是同一套覆盖模型。

## 5. 第四步：SSR/SSGI、TAA 与 SVGF，约 1–2 分钟

**操作**

1. 选“演示 → 4 屏幕空间与时域”。间接光依次选“环境光 / SSR / SSGI”。显示“间接光”，再回最终颜色。
2. 在“渲染 → 后处理与时间”关闭 TAA/SVGF，启动平移回放，观察物体轮廓和间接光。
3. 开启 TAA，观察轮廓；再单独切 SVGF 观察低采样间接光。显示“运动向量 / 方差”，查看 GPU 历史状态。
4. 需要严格重复同一路径时，播放演示包 TAA、SVGF 左右对照视频。左关闭，右开启。

**预期结果**

场景没有移动，变化的是相机。连续帧清单保存每一帧的相机、实际 GPU 路径与完成 serial；不是将一张截图循环播放。SVGF 运行历史矩、方差和多级 à-trous；是否更清晰、是否拖影仍要结合画面判断。

讲解：

> 我用同一个相机轨迹比较开启与关闭。历史不能直接平均，必须重投影并拒绝失配；过滤也有模糊和拖影的取舍。

**边界**：SSR/SSGI 缺少屏幕外和多层遮挡信息；基础 SVGF 未分离漫反射/镜面与反照率解调。视频没有离线真值，不能写成已经证明某个画质指标提高多少。两个正常运动帧的像素差也不能直接当成闪烁误差。

## 6. 第五步：SH/PRT、BVH 与 QEM LOD，约 1–2 分钟

**操作**

1. 选“演示 → 5 预计算（阴影场景）”。间接光设“环境光”，环境漫反射依次切 IBL、SH、PRT。等待“几何与场景资源操作”提示烘焙完成；Ctrl+S 可以持久化。
2. 点击视口物体，底部状态可显示实际 BVH 访问节点及三角形测试次数。选 CPU 路径追踪时说明其执行位置。
3. 选“演示 → 几何与 LOD”，左侧选“LOD curved surface”。在“几何与场景资源操作”点“生成选中网格 LOD 链”。
4. 等待成功后，在“几何与场景资源”开启“自动 LOD”，启动“演示 → 拉远回放 / LOD”。查看“几何：源 → 当前 triangles”。
5. 对照 `video-LOD-left-off-right-on/comparison.mp4` 和 `05-lod-on/frames/sequence.json`。源码网格始终保留。

**预期结果**

PRT 的静态可见性改变环境漫反射，镜面 IBL 不被移除。LOD 真正改变渲染快照的顶点/索引；拉远时使用更少三角形，返回时恢复细节。三个实例共享源网格但可以选择不同级别。几何配置默认显示世界法线，便于观察形状而不让光照与阴影干扰对照；可随时切回最终颜色。

讲解：

> QEM 是先生成减面资源，运行时只选级，不是每帧重新简化。BVH 报告对同一批 192 条射线比较暴力求交与 SAH BVH，检查命中一致，再统计三角形测试数量。

**统计位置**：`05-geometry/stats.json` 保存 BVH probe；`summary.json` 保存 LOD 运动中的最小/最大实际三角形数。BVH 小区间计时不等于整个路径追踪加速，更不是 GPU FPS。

**边界**：PRT 是九系数静态漫反射；QEM 当前输入上限 4096 三角形，保留接缝但没有全局自相交检查和 geomorph；CPU 参考路径追踪不是硬件光追。

## 7. 一次生成可复查演示包

关闭工作台后，在引擎根目录的 PowerShell 中运行一行：

```powershell
.\scripts\export-resume-demo.ps1
```

脚本会构建并串行运行，创建新的输出目录，不覆盖旧资料。默认 640×360、72 个运动帧、视频时间轴 24 FPS；每组性能采样 60 个有效完成帧。编码工具使用 Windows Media Foundation，不需要 ffmpeg 或 Python。

启动、导出和回归脚本会查找本机已安装的 Vulkan SDK，只设置当前进程的运行环境，不修改系统设置。报告同时记录验证层 manifest 与各 GPU 进程是否实际输出 `validation: enabled`；SDK 配置成功而实际没有加载，会使本次检查失败。性能报告需连同验证层状态一起看，不与不同状态的旧报告直接比较。

已构建时可指定新目录：

```powershell
.\scripts\export-resume-demo.ps1 -SkipBuild -OutputDirectory .\output\resume-demo-new
```

| 文件 | 用途与限制 |
|---|---|
| `command.json`、stdout/stderr | 本组参数、程序 SHA256、执行与校验错误 |
| `result.bmp / result.pfm` | 显示图 / 线性 HDR；曝光与 sRGB 不混用 |
| `stats.json` | 实际路径、可见对象、几何数量与白炉中心值 |
| `frames/sequence.json` | 对应捕获帧的 serial、相机与 LOD；GPU 完成统计另标 serial |
| `frames/frame-*.bmp` | 每一帧真正读回后的图片，不重复静态图 |
| 四组 `video-*/comparison.mp4` | 左右同索引帧；编码后验证尺寸、时长、首尾可解码 |
| 六组 `benchmark-*/gpu-timings.json` | 无 HDR 读回的独立正常 GPU 区间；不是 CPU 帧时间 |
| `cases.json / summary.json` | 完成情况、数值检查、环境和统计；失败写 `failure.json` |

视频导出采用逐帧读回，会额外等待 Fence。因此**视频播放帧率与捕获耗时不能作为实时 FPS**。性能样本另跑，不与捕获样本混合。TAA/SVGF 画质需要人工看对照，脚本不会伪造“全部更好”的断言。

## 8. 现场异常处理

| 现象 | 处理 |
|---|---|
| 没有“演示”菜单 | 运行 `start-resume-demo.ps1 -Rebuild`，不要拿旧 exe 演示 |
| PRT 没变化 | 先选“间接光 = 环境光”，等后台烘焙和 GPU 上传完成 |
| LOD 数量不变 | 用固定曲面，先生成链，再开启自动 LOD；两个三角形地板可能不能减面 |
| 拖动鼠标后回放停止 | 这是设计行为；重新启动回放，或手动操作 |
| GPU 配置回退 CPU | 读清提示并换受支持配置；导出脚本拒绝把 CPU 冒充 GPU |
| 计时 unavailable | 展示功能与数量，不报 0 ms；查看独立性能报告 |
| 输出目录已存在 | 选择新目录；不要删除旧证据来重跑 |

源代码入口：`engine/lab/resume_demo.cpp`（配置/回放/射线 probe）、`app.cpp`（菜单、捕获与统计）、`demo_video.cpp`（真实帧左右编码）、`scripts/export-resume-demo.ps1`（固定批次）。
