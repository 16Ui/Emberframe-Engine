## 先看整个系统：这些专题分别补哪一环

渲染首先需要把几何变成可靠的屏幕采样。D01—D05 补上裁剪、共享边、纹理足迹、深度精度与 CPU/GPU 对照，避免后续复杂光照掩盖基础错误。

要比较光照近似，还需要能查询三维几何、能估计积分的工具。D06—D10 建立包围体、BVH、八叉树、采样和离线路径追踪；CPU 参考渲染器与实时 Vulkan 路径共享场景含义，但不必共享同一执行方式。

接下来分两类工作：一类决定表面如何反射及怎样低成本积分，D11—D16 负责 SH/PRT、IBL 预计算、微表面能量补偿、Disney 分量和面积光；另一类决定大量灯怎样进入着色，D17—D18 负责前向/延迟与灯列表。

表面接到多少光还依赖可见性与场景反弹。D19—D21 比较统计阴影；D22—D23 从屏幕数据估计反射和间接光；D26—D30 用光源表面样本、网格、体素或距离场查询三维信息。屏幕方法缺少场外数据，三维方法增加内存和离散误差，没有哪条路线无条件最好。

D24—D25 重建有噪声的光照信号，不能把缺失几何“降噪回来”。D31 探索非真实感表达；D32 统一所有实验的输入、输出、误差与性能证据。

## 统一数据与工程约定

一个共享场景可以被 CPU 光栅化、CPU 路径追踪、GPU 前向和 GPU 延迟路径读取。所有路径固定同一网格、材质、光源单位与相机定义；API 的裁剪/深度差异由适配层显式转换，不让它们偷偷进入 BRDF。

多种算法可以共用 Depth、Normal、Material、Motion Vector 等数据；每种算法仍声明自己的读写范围和历史生命周期。C3 管理资源所有权，C4/C5 管理材质与反射计算，C6 管理 Pass（一次指定输入输出的渲染/计算阶段）依赖与同步，C7 管理上传/缓存，C8 管理可见性，C10/C12 管理测量与回归。上述 C 能力尚未全部实现，GPU 专题接入前须核对实际前置；CPU 实验可以独立先做。

主线输出是线性 HDR 颜色：直接光、间接漫反射、间接镜面、自发光分开保存和检查，最后再后处理、曝光、Tone Mapping 与 sRGB 输出。针对同一间接分量的 IBL、SSGI、RSM、LPV、VCT 不直接全量相加；实验可切换，正式融合需明确覆盖区域、置信度与防重复计数。SSR 与镜面 IBL 同样需要明确融合。

CPU 创建和填写资源/配置、准备场景、录制命令；GPU 只在提交后执行 Shader、复制和绘制。预计算可能由 CPU 离线完成，也可能由 GPU 批处理完成，缓存必须记录约定和版本。读回验证等待 GPU 完成；跨帧历史不当作仅一帧存活的临时图片。

## D01：齐次裁剪：先裁三角形，再除以 w

前置：A5/A6 的坐标变换与插值；不修改已完成的 A 章，新增独立 CPU 实验。

### 解决什么，为什么接在这里

一个三角形的部分顶点可能越过近平面。整块丢弃会缺面，直接除以 w 会产生巨大坐标或翻转；限制屏幕包围盒只能减少遍历，不能修正这种几何错误。

### 数据怎样交给下一步

输入是三个 Clip 四维位置以及 UV、法线等未做透视除法的属性。逐个裁剪平面判断内外，跨越边计算交点并按同一边参数插值属性；裁后多边形重新三角化，再除以 w、做 Viewport 和光栅化。一个输入三角形可以产生零个或多个输出三角形。

### CPU/GPU 与工程落点

CPU 实现逐平面多边形裁剪，并给新顶点保留完整属性；GPU 实验使用默认固定功能裁剪作对照。先固定 Vulkan 的 -w≤x,y≤w、0≤z≤w 约定；旧 CPU 若采用 -w≤z≤w，必须明确转换，不能直接比较两者。

### 实验与验收

三角形分别跨六个平面、一个顶点在相机后、贴近平面移动、完全在外、退化交点。保存裁前/裁后顶点与三角形数量，验证无 NaN/Inf、UV 连续、结果不因顶点顺序改变。明确数值容差，不把额外 w 容差检查当成缺失的裁剪平面。

### 能够回答的问题

为什么不能用屏幕包围盒代替齐次裁剪？裁剪产生的新顶点为什么也必须插值 UV？

来源：[Vulkan 裁剪与光栅化规范](https://docs.vulkan.org/spec/latest/chapters/primsrast.html)

## D02：共享边覆盖与 Top-left rule（顶边/左边规则）

前置：D01；A3 的边函数、绕序和像素中心采样。

### 解决什么，为什么接在这里

相邻三角形各自用“边函数≥0”判断覆盖，共享边可能被两边都算入。浮点判断不一致又可能都不算入；深度测试遮住问题，不等于覆盖规则正确。

### 数据怎样交给下一步

输入是裁剪后屏幕顶点和固定采样点。统一绕序，给每条有向边判定是否包含零值边界；内部采样通过所有边测试，共享边的零值只由其中一个三角形接受。输出是覆盖掩码，再把已覆盖采样交给属性插值和深度测试。

### CPU/GPU 与工程落点

CPU 实验实现一致的边函数与包含/排除规则，固定屏幕 Y 向上还是向下后推导判断式；提供整数/定点边函数对照。GPU 用对应光栅化配置验证，承认硬件子像素精度可能不同，而不是用任意 epsilon 宣称等价。

### 实验与验收

把矩形切成两种对角线、反转绘制顺序、平移亚像素、旋转。输出覆盖计数图，内部样本必须恰好覆盖一次；共享边不留缝也不双算，透明叠加不能出现亮线。边界图与颜色图分别验收。

### 能够回答的问题

Top-left rule 解决什么？为什么深度测试不能替代它？换屏幕 Y 方向后为什么不能照抄边判定？

来源：[Vulkan 三角形光栅化规范](https://docs.vulkan.org/spec/latest/chapters/primsrast.html)

## D03：纹理足迹、缩小与过滤

前置：A6/B11：UV、Sampler（采样器）、Mip 分级纹理已认识。

### 解决什么，为什么接在这里

一个屏幕像素可能覆盖很多纹素。只取一个纹素会遗漏高频信息；双线性只混合邻近四个纹素，也不自动解决大范围缩小和斜视。

### 数据怎样交给下一步

输入是透视正确 UV 及其随屏幕位置的变化。估计像素在纹理中的覆盖足迹，选择 Mip 的 LOD（Level of Detail，细节层级），再比较最近邻、双线性、跨两级 Mip 的三线性和沿长轴多采样的各向异性过滤。输出是用于材质计算的颜色或数据值。

### CPU/GPU 与工程落点

CPU 做最近邻、双线性、Mip 生成和显式 LOD；GPU 用 Shader 导数与 Sampler 配置完成四类对照，并检查各向异性 Feature 和设备上限。颜色纹理在正确颜色空间生成平均值；法线贴图需重归一化，不把所有纹理按颜色处理。

### 实验与验收

棋盘格地面、斜视道路和缓慢移动相机；固定纹理、分辨率和相机路径。保存足迹/LOD 调试视图、摩尔纹和帧间闪烁指标、采样 GPU 时间。分别观察放大与缩小，避免把模糊当作抗锯齿成功。

### 能够回答的问题

为什么双线性仍有摩尔纹？Mip 与各向异性分别解决足迹的哪种问题？预过滤 IBL Mip 与普通纹理 Mip 有何不同？

来源：[PBRT 纹理与采样](https://www.pbr-book.org/4ed/Textures_and_Materials)

## D04：深度精度、Z-fighting 与 Reversed-Z

前置：B8/B9 的深度测试；明确投影、深度存储格式和近平面。

### 解决什么，为什么接在这里

两块很近的表面可能量化到同一深度，产生交替覆盖。透视深度不是线性距离；只把比较符号反过来，不会自动改善精度。

### 数据怎样交给下一步

输入是相机投影和可用浮点深度格式。比较普通近0远1与反向近1远0的映射，配套修改清屏值和比较操作。读取深度的世界位置重建、Hi-Z（Hierarchical Z，层级深度）、SSAO/SSR 与阴影路径分别确认自己的约定。

### CPU/GPU 与工程落点

CPU 用双精度计算映射/量化误差作为数值基线；GPU 做有限远平面普通/反向投影及浮点深度对照，进一步验证无限远平面。Camera Reversed-Z 不强迫阴影统计深度一起反向；格式和视空间线性深度分别记录。

### 实验与验收

重叠平面、远景、不同 near/far 比例；记录可区分的最小距离与 Z-fighting 图。验收 Clear=0、GREATER/GREATER_OR_EQUAL 等约定和所有消费者一致；解释共面几何仍可能冲突。

### 能够回答的问题

反向 Z 为什么要结合浮点分布讨论？为什么调大近平面也有帮助？修改后 SSR 深度重建为何会错？

来源：[NVIDIA 深度精度分析](https://developer.nvidia.com/blog/visualizing-depth-precision/)

## D05：CPU/GPU 管线差分验证

前置：D01—D04；正式 C3/C4 的 GPU 资源与几何绘制路径。

### 解决什么，为什么接在这里

CPU/GPU 各自“看起来对”仍可能使用不同裁剪、深度、坐标或采样约定。需要分阶段检查数据，才能确定差异来自几何还是材质。

### 数据怎样交给下一步

同一个场景导出统一顶点、矩阵和纹理。分别生成覆盖、Depth、UV、世界法线、线性 HDR（High Dynamic Range，高动态范围）颜色，再比对中间结果；最后才比较 Tone Mapping 后图片。

### CPU/GPU 与工程落点

CPU 生成参考缓冲；GPU 把检查图像复制到 Readback Buffer（CPU 可读回缓冲），提交后等完成再映射，不能把命令录制当成数据已经返回。GPU 上传/读回职责接 C3/C7，指标与报告接 C10/C12。

### 实验与验收

先比较无纹理单三角形，再裁剪、插值、深度、采样、光照。覆盖边界与内部区域分别统计，数值图用约定的容差；记录最大误差、均方误差及差异热图。关闭或固定随机、曝光、抖动与 MSAA；不要求所有驱动位级一致。

### 能够回答的问题

若 CPU 正确而 GPU 颜色错，如何逐段定位？哪些差异属于约定，哪些可能是硬件精度？

来源：[Vulkan 光栅化规范](https://docs.vulkan.org/spec/latest/chapters/primsrast.html)

## D06：包围体与基础相交测试

前置：A5 的矩阵与世界空间；本章作为 D07/D08 的共同输入层。

### 解决什么，为什么接在这里

每条射线都测试所有三角形成本高，需要先用便宜的包围测试排除不可能命中的对象。包围体只是简化外形，不是 BVH 或八叉树本身。

### 数据怎样交给下一步

从顶点求 AABB（Axis-Aligned Bounding Box，轴对齐包围盒），再比较球和 OBB（Oriented Bounding Box，有向包围盒）。查询输入射线原点、方向和区间；盒体测试返回可进入/离开区间，候选对象再做精确三角形相交。

### CPU/GPU 与工程落点

CPU 实现射线—AABB、球、三角形与世界包围体更新；展示非均匀缩放、旋转后 AABB 的保守更新。GPU 仅可视化或用于 C8 剔除，先让基础相交测试有确定结果。用户写的 BVM 暂按 BVH 理解；若实际指另一模型再单独更名。

### 实验与验收

平行射线、盒内起点、擦边、负方向、退化盒、极近三角形；与暴力遍历比较最近命中和命中距离。报告误剔除必须为零，包围体紧致度与测试数量单独统计。

### 能够回答的问题

## D07：BVH：包围体层次结构

### 解决什么，为什么接在这里

## D09：蒙特卡洛、重要性采样、MIS 与预计算

前置：GAMES101 渲染方程；本章给 D10—D16 的积分实验提供共同工具。

### 解决什么，为什么接在这里

积分需要汇总很多方向或光源点，有限样本不可能逐个遍历。Monte Carlo（蒙特卡洛）用按分布抽取的样本估计积分；重要性采样把样本放在贡献较大的地方，MIS（Multiple Importance Sampling，多重重要性采样）组合互补策略。

### 数据怎样交给下一步

输入被积函数和 PDF（Probability Density Function，概率密度函数）。采样位置/方向、计算贡献并除以对应密度；比较均匀、余弦、光源和 BRDF 采样，用 MIS 权重避免重复计数。固定随机种子做收敛曲线，再把与运行时不变参数有关的积分烘焙成系数或 LUT（Lookup Table，查找表）。

### CPU/GPU 与工程落点

先 CPU 数值实验，后 GPU 批量烘焙。说明面积 PDF 与立体角 PDF 的雅可比换算、低差异序列与随机估计的区别。Russian Roulette（俄罗斯轮盘终止）保留路径时除以存活概率；确定深度截断则单独记录偏差。

### 实验与验收

常数半球积分、Lambert 白炉、大小面积光、光滑/粗糙材质；核对密度归一化，重复多种种子统计误差与方差。比较相同样本预算，不凭一张偶然好看的图判断采样策略。

### 能够回答的问题

为什么要除 PDF？重要性采样是否改变目标积分？MIS 如何同时利用光源和 BRDF 采样？

来源：[PBRT 蒙特卡洛积分](https://www.pbr-book.org/4ed/Monte_Carlo_Integration)

### 最小数学检查：蒙特卡洛估计

先把积分抽象为已知函数 f 在区域 Ω 的总量 I。p 是这个区域上归一化的采样密度，X_i 是按 p 抽出的第 i 个样本，N 是样本数；用帽子表示有限样本估计：

$$
I=\int_{\Omega}f(x)\,dx,
\qquad
\widehat I=\frac{1}{N}\sum_{i=1}^{N}\frac{f(X_i)}{p(X_i)}.
$$

这里 f 非零的区域必须具有非零采样密度，密度和积分使用相同度量。最小检查：在 [0,1] 区间均匀采样时 p=1，若 f 恒为2，每个贡献为2，任何样本数的估计都为2。实际方向光照中 f 包含来光、BRDF 和余弦，不能除 PDF 后再把余弦重复乘一遍。

## D11：SH：球谐环境光表示

前置：B17 环境光、D09 方向积分；D10 可在后续提供参考，不阻塞首个实验。

### 解决什么，为什么接在这里

SH（Spherical Harmonics，球谐）用有限系数近似球面方向函数。它减少存储与求值成本，但低阶不能保留太阳这类高频亮点；表示方法本身不是间接光求解器。

### 数据怎样交给下一步

### 实验与验收

常量环境、单方向亮斑、复杂 HDR；和数值半球积分/漫反射 Cubemap 对比，报告误差、系数存储和 GPU 时间。显示振铃和负值，记录任何钳制导致的偏差。

## D12：PRT：预计算辐射传输

前置：D07/D09/D11；静态网格；D10 相交与路径工具可复用。

### 解决什么，为什么接在这里

PRT（Precomputed Radiance Transfer，预计算辐射传输）预先记录表面对不同入射方向的响应，包含余弦、可见性乃至互反射。仅有 SH 环境并不知道物体自遮挡，这就是传输数据补上的信息。

### 数据怎样交给下一步

CPU 烘焙并缓存每顶点传输；GPU 插值/求值，支持物体刚体旋转与环境旋转。几何变形和新增遮挡会使静态传输失效；缓存键包含网格、材质、采样约定与版本。Glossy 不要求完整产品级压缩，但不能只在文档提到矩阵。

### 实验与验收

前置：B15/B17；D09/D13；保留单次散射 GGX 对照。

## D17：Forward / Deferred：光照在哪一遍计算

前置：C3—C6 的几何、材质、Image 与多 Pass 基础；B15/B16。

### 解决什么，为什么接在这里

Forward Rendering（前向渲染）在绘制表面时直接算光照；Deferred Shading（延迟着色）先保存可见表面的材质信息，后按屏幕计算光照。它们改变数据组织与执行时机，不是两套不同的 BRDF。

### 数据怎样交给下一步

共享场景和材质。Forward 的几何 Pass 直接输出 HDR；Deferred 的几何 Pass 输出 G-buffer（Geometry Buffer，保存法线、材质、深度等表面信息的多张图像），Lighting Pass 再读它们算 HDR。世界位置可由深度重建，透明物体使用单独前向路径。

### CPU/GPU 与工程落点

GPU 两条可切换路径共用 BRDF/灯数据；CPU 管理格式和 Pass 资源。记录 G-buffer 每像素字节数、法线编码、深度重建、MSAA 与透明处理。读写切换接 C6 Barrier，材质系统接 C4/C5。

### 实验与验收

少灯/多灯、低/高 Overdraw（重复覆盖）、透明物体、不同分辨率；对比相同画质的 GPU 时间、图像误差、G-buffer 显存和估算读写带宽。保存 BaseColor/Normal/MR/Depth 分项。

## D18：Tiled / Clustered：多光源候选列表

前置：D17；C8 可见性与 C10 测量；GPU Compute 和 Buffer 同步。

### 解决什么，为什么接在这里

每片元遍历全部灯会重复做无用计算。Tiled Shading（分块着色）按屏幕块建立候选灯表；Clustered Shading（聚簇着色）进一步按深度等信息分组，减少同屏不同深度表面的候选灯。它们可与前向或延迟组合。

### 数据怎样交给下一步

CPU 上传灯参数与相机。GPU 构造 Tile 或三维 Cluster 边界，灯范围相交筛选后输出索引列表及每组的 offset/count；着色点找到所属组，仅遍历列表计算直接光。一个灯可进多个组，一个组也可含多个灯，列表只是候选，不代替 BRDF 与阴影。

### CPU/GPU 与工程落点

先 CPU 暴力列表校验，再 GPU 灯表；统一灯衰减截断误差、方向光全局列表、列表容量与溢出回退。透明像素的列表不能只依赖不透明深度范围而漏灯；GPU 写列表到着色读列表需要依赖同步。

### 实验与验收

随机灯、密集重叠灯、前后景深度断层、空块、透明物体。报告灯数量、平均/最大候选数、溢出次数、列表显存、构建/着色 GPU 时间及 CPU 成本；与全灯遍历图像比较。

### 能够回答的问题

来源：[Olsson 等 Clustered Shading](https://www.cse.chalmers.se/~uffe/clustered_shading_preprint.pdf)

## D19：VSM 与 SAT：矩统计与区域查询

前置：B18 PCF/PCSS；先固定线性光源深度“越大越远”。

### 解决什么，为什么接在这里

VSM（Variance Shadow Maps，方差阴影贴图）保存深度的一、二阶矩，用均值和方差估计区域可见比例；SAT（Summed-Area Table，积分图/区域累加表）保存二维前缀和，快速取矩形区域统计量。SAT 不负责判断遮挡，可以服务 VSM/VSSM。

### 数据怎样交给下一步

光源 Pass 在深度测试后写 z 和 z²。Blur/Mip 或 SAT 查询得到区域平均矩，算方差并用 Cantelli 单侧切比雪夫不等式估计可见性上界；Camera Lighting 用它衰减对应直接光，而不是把所有 IBL 一起乘暗。

### CPU/GPU 与工程落点

CPU 双精度矩与矩形求和基线；GPU VSM、可分离过滤、SAT 两维前缀计算与区域读回。约定边界、矩形面积、深度范围和最小方差；记录大 SAT 累加再相减的消减误差，保留高精度与低带宽格式对照。

### 实验与验收

单层平面、双层遮挡、多峰深度、宽核；四次 SAT 查询与暴力求和一致到容差。显示均值/方差/上界和漏光，比较 PCF 的真实比较平均、VSM 估计、SAT 构建+查询成本及显存。

### 能够回答的问题

为什么深度平方可以过滤，而平均深度再做一次比较不行？切比雪夫给的是比例上界还是精确比例？SAT 为什么可能损失精度？

来源：[Lauritzen：Summed-Area Variance Shadow Maps](https://developer.nvidia.com/gpugems/gpugems3/part-ii-light-and-shadows/chapter-8-summed-area-variance-shadow-maps)

### 最小数学检查：输出是可见性上界

令 Z 是核内最近表面的线性深度随机变量，t 是当前接收点的同尺度深度；Z≥t 表示该样本没有比接收点更近的遮挡。μ 是平均深度，m₂ 是深度平方平均，σ² 是方差：

$$
\mu=\mathbb E[Z],\qquad
m_2=\mathbb E[Z^2],\qquad
\sigma^2=m_2-\mu^2.
$$

在 t>μ 时，单侧切比雪夫（Cantelli）给出：

$$
\Pr(Z\ge t)
\le
\frac{\sigma^2}{\sigma^2+(t-\mu)^2}.
$$

VSM 把右边用作可见比例近似；t≤μ 时通常取估计1，而不是证明真实可见比例一定为1。检查深度 [0.2,0.2,0.4,0.8]：μ=0.4、m₂=0.22、σ²=0.06。t=0.7 时上界为0.4，真实比例为0.25；差异能解释漏光。[VSM 作者的统计与过滤说明](https://developer.nvidia.com/gpugems/gpugems3/part-ii-light-and-shadows/chapter-8-summed-area-variance-shadow-maps)

## D20：VSSM：统计近似 PCSS 遮挡者搜索

前置：D19；B18 PCSS 的搜索、半影估计、最终过滤三阶段。

### 解决什么，为什么接在这里

VSSM（Variance Soft Shadow Mapping，方差软阴影映射）把 VSM 统计估计用于 PCSS 的大区域搜索与过滤。它既用到比例估计，也近似求平均遮挡深度；并不是只做前者或只做后者。

### 数据怎样交给下一步

搜索区域获得平均深度与可见比例估计。将区域分为比接收点近的遮挡者和其余样本，在特定假设下求条件遮挡均值；用光源尺度与遮挡/接收深度估计半影宽度，再以对应核查询矩统计并算可见性。

### CPU/GPU 与工程落点

GPU 用 SAT 或另一种已说明的区域统计后端；CPU 使用显式逐样本遮挡列表给比例和条件均值基线。处理全亮、全遮挡、遮挡比例接近零与深度模型不匹配；实现区域细分对照来展示漏光改善及额外成本。

### 实验与验收

单遮挡层、多遮挡层、接触/离远的接收面、大半影。分别比较遮挡比例、平均遮挡深度、半影宽度和最终阴影，不只比较总颜色；报告与同搜索预算 PCSS 的成本及近似偏差。

### 能够回答的问题

VSM 结果怎样参与 VSSM？为什么不能从两个矩恢复所有遮挡位置？平均遮挡深度近似依赖什么假设？

来源：[Yang 等 VSSM 原论文](https://jankautz.com/publications/VSSM_PG2010.pdf)

### 最小数学检查：条件平均不是全区域平均

μ 是整个搜索区域的平均深度；v 是非遮挡部分的比例，μ_non 是非遮挡部分平均深度，μ_block 是遮挡部分平均深度。两部分的加权平均满足：

$$
\mu=(1-v)\mu_{\mathrm{block}}+v\mu_{\mathrm{non}}.
$$

GAMES202 的简化估计把 μ_non 近似为接收深度 t，并使用统计估计的 v，于是：

$$
\mu_{\mathrm{block}}
\approx
\frac{\mu-vt}{1-v}.
$$

例如 μ=0.5、v=0.25、t=0.8，近似遮挡均值为0.4。混合恒等式是精确的；v 的统计估计和 μ_non≈t 都是近似，不能把后式说成总能恢复真实遮挡深度。v 接近1时需无阻挡/回退处理；实现还须核对原论文的区域细分与适用深度约定。[VSSM 作者原论文](https://jankautz.com/publications/VSSM_PG2010.pdf)

## D21：MSM：四矩阴影与数值稳定性

前置：D19 的矩过滤、VSM 漏光案例；不依赖 VSSM 完全实现。

### 解决什么，为什么接在这里

MSM（Moment Shadow Mapping，矩阴影映射）利用更多矩信息约束深度分布，提高相对于两矩估计的表现。它仍是有限统计量近似，不是恢复每个遮挡者的精确位置，也不自动替代 PCSS 的半影宽度求解。

### 数据怎样交给下一步

光源 Pass 保存前四阶矩，线性过滤后按明确选定的 MSM 变体重建可见性界限/估计，再给 Lighting 用。存储变换、moment bias（矩偏置）和数值分支共同保证求解稳定，不可随意混用作者不同变体。

### CPU/GPU 与工程落点

先 CPU 双精度实现作者算法与病态输入测试，再 GPU Shader；比较原始四矩、作者优化编码、16/32 位存储与所需能力。采用作者代码须核对许可和改动，并将 Shadow 读写接 C6。

### 实验与验收

复用 D19 双层/多峰漏光场景，加常深度近零方差、端点深度和宽过滤核。报告漏光/过暗误差、偏置敏感性、失败计数、显存带宽与 GPU 时间；VSM/MSM 用同分辨率、同核对照。

### 能够回答的问题

多两个矩为何增加约束，但仍非精确分布？MSM 为何需要偏置？是否得到硬阴影质量就等于完整软阴影？

## D22：SSR：屏幕空间反射

前置：D04 深度约定、D17 G-buffer、B17 IBL；后续 D24/D25 用于去噪。

### 解决什么，为什么接在这里

SSR（Screen-Space Reflections，屏幕空间反射）从当前相机深度和颜色中寻找反射命中，不重新遍历全部三维场景。只存了可见表面，因此屏幕外、被遮住的表面和背面信息会缺失。

### 数据怎样交给下一步

重建着色点与法线，按镜面方向或粗糙 BRDF 采样方向沿屏幕深度追踪；由粗步进到 Hi-Z 加速/细化定位，用厚度规则判断命中。读取已照亮的场景颜色，按材质反射权重生成 SSR 分量和置信度；未命中/低置信度回退环境镜面 IBL。

### CPU/GPU 与工程落点

GPU 先线性 Ray March（沿射线逐步查询）再 Hi-Z；CPU 只配置/记录和读回检查。分离不含本轮 SSR 的源颜色、反射图与合成输出，避免原位读写和跨帧无限反馈。边缘渐隐和回退是近似，不是补出真实场外几何。

### 实验与验收

镜面地板、粗糙球、屏幕边缘物体、薄墙、移动遮挡；输出步数、命中、厚度、置信度与失败图。比较 D10 参考及 GPU 成本，解释反射视方向与源图视方向不同造成的颜色误差。

### 能够回答的问题

为什么 SSR 会漏屏外物体？Hi-Z 怎样减少步数？SSR 与 IBL 为什么不能不加区分地全量相加？

来源：[AMD 屏幕空间反射技术文档](https://gpuopen.com/manuals/fidelityfx_sdk/techniques/stochastic-screen-space-reflections/)

## D23：SSGI：屏幕空间间接光

前置：D09 的采样/PDF、D17/D22 的深度重建；D24/D25 降噪。

### 解决什么，为什么接在这里

SSGI（Screen-Space Global Illumination，屏幕空间全局光照）从屏幕可见数据近似获取一次间接来光。本章主线是漫反射间接光，不是 SSR 换名字，也不是 AO 可见性乘一份固定环境色。

### 数据怎样交给下一步

在着色点的法线半球采样方向，屏幕追踪得到命中点，读取其直接受光/自发光颜色作为回传近似。按本点 BRDF、余弦与 PDF 汇总样本，形成线性间接光；再降噪并与直接光、发光项及明确分配的其他 GI 来源合成。

### CPU/GPU 与工程落点

GPU 低样本估计，保留深度、法线、源颜色和命中记录。源颜色不含本轮 SSGI，先实现严格的一次近似而非无控制反馈；说明命中处出射方向被相机颜色替代的限制。与同一漫反射分量的 IBL/RSM/VXGI 切换或按覆盖融合。

### 实验与验收

彩色墙反弹、接触处、屏外光源/墙、前景遮挡和移动相机；固定样本/种子，对比仅直接光、AO、SSGI 和 D10 一跳参考。记录噪声、漏光、间接能量、追踪与去噪 GPU 时间。

### 能够回答的问题

SSGI 为什么能产生颜色渗透而 AO 不行？为何不能拿已含间接光的总颜色反复采样？屏幕数据缺失能否靠降噪补回来？

来源：[GAMES202 屏幕空间全局光照课程与阅读材料](https://sites.cs.ucsb.edu/~lingqi/teaching/games202.html)

## D24：HW5：时空降噪完整链路

前置：GAMES202 HW5 记录；B20 TAA、D09；D10 低 SPP 序列或 D22/D23 噪声图。

### 解决什么，为什么接在这里

降噪利用空间相邻、时间连续的信号减少有限采样噪声，但必须避免把不属于同一表面的历史和邻域混进去。HW5 的核心不能被缩成“历史平均”一句话。

### 数据怎样交给下一步

输入当前噪声线性颜色、深度/位置、法线、对象标识和上一帧变换。先做 Joint Bilateral（联合双边）空间过滤；把同一表面重投影到历史位置，检验深度/法线/对象和屏幕边界，钳制历史到当前邻域合理范围，再时间累积。输出过滤颜色及新历史，保留当前和上一帧的独立资源。

### CPU/GPU 与工程落点

CPU 先复习作业实现，再 GPU 独立去噪 Pass；静态几何用 View/Projection，移动物体还需前后 Model 或可靠 Motion Vector（运动向量）。明确运动方向、jitter 补偿、历史 ping-pong、Camera Cut/Resize 清空；反遮挡没有旧历史时降低或重置权重。

### 实验与验收

静止低样本、移动物体、突然露出的背景、灯光突变、相机切换；对比空间-only、时间-only、完整流程。输出历史有效掩码、历史长度/权重和误差图，测噪声衰减、拖影、响应帧数与 GPU 成本。

### 能够回答的问题

为什么不能把同屏坐标上一帧颜色直接平均？双边权重阻止混合什么？历史钳制和历史拒绝有何不同？

来源：[GAMES202 HW5 对应实时光追与降噪课程](https://sites.cs.ucsb.edu/~lingqi/teaching/games202.html)

### 最小数学检查：累积前必须已经匹配表面

C_t 是当前有效过滤颜色，H_prev 是经重投影、验证和钳制的历史颜色，a 是当前帧权重，H_t 是新历史：

$$
H_t=aC_t+(1-a)H_{\mathrm{prev}},\qquad 0\le a\le1.
$$

a=0.1、当前通道0.2、有效历史0.8，得到0.74。若历史无效，就重置或改用当前帧，不能仍给错误历史90%权重。小 a 降噪更强但响应更慢；这是指数移动平均，不代表所有历史帧等权。

## D25：SVGF：方差引导的多尺度过滤

前置：D24；低样本间接光，稳定的几何引导信号。

### 解决什么，为什么接在这里

SVGF（Spatiotemporal Variance-Guided Filtering，时空方差引导滤波）在时域重建后估计噪声强弱，再有控制地进行多尺度空间过滤。它重建光照采样信号；TAA 主要重建跨帧像素采样，两者相关但并不等同。

### 数据怎样交给下一步

重投影有效历史并累积颜色与亮度的一、二阶矩，结合历史长度估计方差；历史短处用局部统计补足。用 à-trous（带间隔采样的多尺度滤波）逐级扩大足迹，同时用深度、法线、亮度与方差限制跨边缘混合，输出去噪光照。

### CPU/GPU 与工程落点

GPU 矩/历史/方差/多层滤波分 Pass 实现；CPU 对固定噪声序列校验统计。先漫反射 GI，再验证粗糙 SSR 的不同引导需求；若分离 albedo 过滤，需处理零值和重乘约定，不能把高频纹理涂掉。

### 实验与验收

低 SPP 路径序列与 SSGI 对照；薄物体、纹理边缘、亮点、运动/反遮挡、短历史。保存每层结果和方差/历史图，测空间偏差、时间稳定与拖影，以及每 Pass 成本/显存。

### 能够回答的问题

为何需要方差而不只是固定模糊半径？à-trous 为什么能扩足迹？增加历史与加大滤波为何可能更稳定却更糊？

来源：[Schied 等 SVGF 原论文入口](https://research.nvidia.com/publication/2017-07_spatiotemporal-variance-guided-filtering-real-time-reconstruction-path-traced)

## D26：RSM：反射阴影贴图的一次间接光

前置：B18 光源视角阴影；D09；D17 表面数据。

### 解决什么，为什么接在这里

RSM（Reflective Shadow Maps，反射阴影贴图）不仅保存从光源看到的最近深度，还保存受光表面的世界位置、法线和反射通量，把这些表面样本作为间接光来源。它不是普通 Shadow Map 自动增加反弹。

### 数据怎样交给下一步

从光源渲染最近受光表面，构成 VPL（Virtual Point Light，虚拟点光源）样本。相机着色点抽取这些样本，根据两端朝向、距离、样本权重与本点材质累计一次漫反射。反射通量与单纯显示颜色不同，必须包含样本代表的光能/面积约定。

### CPU/GPU 与工程落点

GPU 多 Attachment 光源 Pass 和采样 Gather（汇集贡献）；CPU 精确样本求和基线。先记录“未求二次可见性”的经典近似，再用 D07 CPU 射线测试小场景展示遮挡影响；近距离奇异值、样本密度和半径限制都标为偏差来源。

### 实验与验收

彩色墙、直角拐弯、隔墙漏光、RSM 未看到的面；对比普通阴影、RSM 与 D10 一跳。检查改变 RSM 分辨率不会无理由把能量倍增，报告样本数、RSM 显存、间接误差与 GPU 时间。

### 能够回答的问题

RSM 为什么要记录位置/法线/通量？哪里的一次反弹被近似了？为什么它可能穿墙漏光？

## D27：LPV：光传播体积

前置：D11 SH、D26 RSM；三维网格定位。

### 解决什么，为什么接在这里

LPV（Light Propagation Volumes，光传播体积）把受光表面样本的方向光能注入三维网格，用相邻格子传播近似低频间接光。一个格子用低阶 SH 存方向分布，不是每个格子一盏精确点光。

### 数据怎样交给下一步

每帧清空/初始化本帧体积，RSM 样本按世界位置注入并编码方向；传播若干轮，用 ping-pong 网格分离本轮读写，必要时以 Geometry Volume（几何体积中的遮挡信息）抑制穿透。着色点插值邻近格子的 SH，用法线求漫反射间接光。

### CPU/GPU 与工程落点

先 CPU 单格/两格传播，再 GPU 网格与遮挡体积；扫描网格尺度和迭代数，添加小型级联 LPV 对照。照明更新应重置新注入，不能把传播轮次或跨帧积累误写成严格物理反弹次数。

### 实验与验收

彩色墙、薄墙、小房间/大空间、动态灯和移动几何；显示格子方向、注入/每轮传播。记录漏光、能量漂移、内存、注入/传播/查询时间，与 RSM/D10 对比。

### 能够回答的问题

SH 在 LPV 里存什么？粗网格为什么漏光？传播次数为何不是路径追踪的反弹次数？

来源：[Kaplanyan、Dachsbacher：Cascaded LPV](https://cg.ivd.kit.edu/publications/p2010/CLPVFRII_Kaplanyan_2010/CLPVFRII_Kaplanyan_2010.pdf)

## D28：体素化、三维 Mip 与稀疏体素结构

前置：D08；C3/C6 的 3D Image 与同步；本章为 D29 提供数据。

### 解决什么，为什么接在这里

Voxel（体素）用小立方区域表示场景占用与光照数据。直接沿三角形追踪复杂，因此先建立可快速按空间位置查询的离散表示；体素化本身还没有完成全局光照。

### 数据怎样交给下一步

把世界空间三角形转换到固定网格，保守记录被覆盖格子的占用、材质/法线，注入直接受光的出射光信息；构建带明确定义的辐亮度/不透明度层级。先密集 3D 纹理，再稀疏八叉树保存非空区域，输出给锥体查询。

### CPU/GPU 与工程落点

GPU 保守体素化与并发写入聚合；CPU 小网格三角形覆盖参考及八叉树构建。定义同格多表面冲突、方向信息存储、动态物体清除/更新和 Mip 聚合规则，避免无脑平均 RGB/alpha 导致能量或遮挡错误。

### 实验与验收

轴对齐/斜薄墙、小孔、多表面同格、动态移走物体；可视化切片、层级、占用和辐亮度。报告占用率、密集/稀疏内存、生成更新时间以及保守覆盖的漏格/多格数量。

## D29：VXGI / VCT：体素全局光照与锥体追踪

前置：D28；B15/B17；D09 的积分与采样解释。

### 解决什么，为什么接在这里

VXGI（Voxel Global Illumination，体素全局光照）是一类用体素场近似全局光照的路线；本项目明确实现 VCT（Voxel Cone Tracing，体素锥体追踪）教学方案，不把它冒称完整 NVIDIA VXGI SDK。

### 数据怎样交给下一步

从表面向半球发出若干锥体，锥宽随距离扩大，选择对应 3D Mip 获取空间过滤的光和不透明度，按透射率前后累积。若干漫反射锥汇总间接光；镜面方向用与粗糙度相关的锥，最后与直接光等分项合成。

### CPU/GPU 与工程落点

GPU 读取层级体素场并输出漫反射/镜面/遮蔽分量；CPU 单锥积分对照。明确起点偏移、步长、锥角、LOD 和 opacity 累积；增加第二次注入实验时必须区分场景反弹与同一贡献反复反馈。

### 实验与验收

同屏与屏外彩色物体、薄墙、大空旷区域、粗糙/光滑反射；对比 SSGI、RSM、LPV 与 D10。保存锥体 LOD/步数、透射率和分项图，统计漏光、过度模糊、更新+追踪 GPU 成本与显存。

### 能够回答的问题

锥体为什么查不同 Mip？体素解决屏幕空间什么信息缺失，又新增什么误差？光滑镜面为什么是困难案例？

来源：[NVIDIA：Interactive Indirect Illumination Using Voxel Cone Tracing](https://research.nvidia.com/labs/rtr/publication/crassin2011givoxels/)

## D30：SDF：有符号距离场、追踪与阴影

前置：D06/D08；世界/局部变换和体积采样。

### 解决什么，为什么接在这里

SDF（Signed Distance Field，有符号距离场）在空间点保存到最近表面的距离，并用正负区分内外。它是几何表示，不是完整 GI；距离查询可用于 Sphere Tracing（球面追踪）的安全步进、法线与阴影。

### 数据怎样交给下一步

先用球/盒解析距离，再从闭合网格生成离散距离场。沿射线查询距离、在安全下界条件下前进、接近零时判命中；梯度给法线。向光源方向追踪做硬阴影，再比较经验软阴影启发式；软化并不等于精确面积光可见性积分。

### CPU/GPU 与工程落点

CPU 解析基线和网格距离/符号烘焙；GPU 3D 纹理查询与步进。解释网格非闭合的符号歧义、插值/离散误差、非均匀缩放可能破坏真实距离；用保守界/安全系数并验证，不能只给普通距离函数就保证不越面。

### 实验与验收

球/盒、薄墙、相交模型、非均匀缩放、相机在内部和掠射；比较解析/三角形相交。报告命中距离误差、漏面、步数、烘焙/显存/运行成本，显示距离切片与梯度。

### 能够回答的问题

为什么可以按距离前进而不是固定步长？什么条件保证不穿透？SDF 的软阴影是否是真实半影？

来源：[Hart：Sphere Tracing 原论文](https://graphics.stanford.edu/courses/cs348b-20-spring-content/uploads/hart.pdf)

## D31：NPR：卡通、描边与织线风格实验

前置：B15/B16 的法线/光照；D17 的深度/法线图；C6 后处理。

### 解决什么，为什么接在这里

NPR（Non-Photorealistic Rendering，非真实感渲染）以风格规则替换或改造真实感的颜色表达。它仍需几何、光照、可见性和稳定采样，不是随意给最终截图加滤镜。

### 数据怎样交给下一步

同一场景先得到表面朝向/光照与遮挡，再将明暗映射为 Toon（卡通）色带；轮廓分别用反向外壳几何和屏幕深度/法线边缘检测生成；Hatching（排线）按明暗选择纹理/密度，最后合成风格化画面。

### CPU/GPU 与工程落点

GPU 实现三类最小实验，材质声明风格参数。描边厚度区分世界和像素单位，非均匀缩放后法线正确；色带阈值、纹理过滤和历史策略统一，明确风格目标不以 PBR 白炉“物理误差”评价。

### 实验与验收

光源移动、物体旋转、远近变化、轮廓遮挡和连续相机；记录边缘漏检/误检、描边像素宽度、色带抖动与 GPU 时间。保存普通 PBR/卡通/两种描边/排线对照，而不是只展示最终风格图。

### 能够回答的问题

NPR 改变管线的哪一层？两种描边的遮挡和宽度限制分别是什么？排线为什么也会有纹理缩小闪烁？

来源：[GAMES202 NPR 课程与阅读入口](https://sites.cs.ucsb.edu/~lingqi/teaching/games202.html)
