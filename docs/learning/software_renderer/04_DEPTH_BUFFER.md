# Software Renderer 第四课：深度缓冲

本课解决的问题是：多个三角形覆盖同一个像素时，怎样让距离观察者更近的表面可见，而不是简单让后提交的三角形覆盖前一个。

对应源码：[samples/software_renderer/04_depth/main.cpp](../../../samples/software_renderer/04_depth/main.cpp)。

## 1. 输入与输出

| 字段 | 内容 |
|---|---|
| 输入 | 带二维位置、深度和颜色的三个顶点 |
| 复用 | 第三课的包围盒、边函数和重心坐标 |
| 新计算 | 插值当前像素深度，与已保存深度比较 |
| 输出 | 正确保留近处三角形的颜色图片 |
| 本课不做 | 透视矩阵、裁剪、透明物体和 GPU 同步 |

## 2. Depth Buffer 是什么

Depth Buffer 的中文含义是深度缓冲区。它是一份与 Framebuffer 尺寸相同的数据：

```text
Framebuffer[x, y] 保存当前可见颜色
DepthBuffer[x, y] 保存当前可见表面的深度
```

它们不是同一种数据。颜色回答“这里显示什么颜色”，深度回答“当前颜色对应的表面离观察者多远”。

本课约定深度范围为 `0～1`，数值越小表示越近。初始值设为正无穷，表示还没有任何表面占据像素。

## 3. 像素深度从哪里得到

三角形只有三个顶点深度，而内部有很多像素。第三课已经得到重心权重 `α、β、γ`，因此可以插值：

```text
pixelDepth = α × depthA + β × depthB + γ × depthC
```

这说明重心坐标不是只用于颜色；只要是定义在顶点上的可插值属性，都可以沿用同一组权重。

## 4. 深度测试与写入顺序

对每个三角形内部像素：

1. 计算当前三角形在该像素的深度；
2. 读取 DepthBuffer 中已有深度；
3. 当前深度更小时，更新深度并写入颜色；
4. 当前深度更大或相等时，丢弃这次颜色写入。

示例：DepthBuffer 当前为 `0.8`，新片元深度为 `0.2`。因为 `0.2 < 0.8`，新片元更近，应覆盖颜色并把深度改成 `0.2`。之后再提交深度 `0.6` 的片元时，它会被拒绝。

源码故意先画近处蓝色三角形，再画远处橙色三角形。这样可以证明重叠区域的结果来自深度比较，而不是绘制顺序。

## 6. 与 Vulkan 的关系

Vulkan 的 Depth Image 在 GPU 内存中承担相同职责，Graphics Pipeline 的深度测试阶段完成比较和写入。CPU 版本让我们能直接观察深度数组和比较条件，Vulkan 版本则把同样的逐像素工作并行交给 GPU。
